# George-Bot-2026

アンジュのプログレス検索・ガチャ・おみくじ・クイズと、ジョージとの会話を提供するDiscord Bot。
コードの案内と変更時の注意は、末尾の開発ガイドを参照してください。

## 起動

Python 3.11以上で、依存関係をインストールして起動します。

```sh
python -m pip install -r requirements.txt
python main.py
```

環境変数は実行環境に設定します。`.env.example` は記入例であり、`.env` の自動読み込みは行いません。

| 変数                 | 用途
| `DISCORD_TOKEN`      | Discord Botのトークン。起動に必須
| `GEMINI_API_KEY`     | 会話・一言生成に使用
| `GEMINI_MODEL`       | 使用モデル。未指定時は `gemini-flash-latest`
| `DATABASE_URL`       | PostgreSQL/Neon。所持・好感度・称号・履歴などの永続化に使用
| `PORT`               | ヘルスチェック用HTTPの待受ポート。未指定時8080
| `GEMINI_DIAGNOSTICS` | `1` の場合、起動時に固定プロンプトで生成診断。通常は `0`

トークンや接続URLをソース・ログ・スクリーンショットへ貼らないでください。

Discord Developer PortalでMessage Content Intentを有効にします。
招待時は `bot` と `applications.commands` を指定します。
チャンネルの閲覧・送信・履歴閲覧・リアクション追加・埋め込みリンク・ファイル添付の権限が必要です。
称号の装着には「ロールの管理」と、称号ロールより上位に置いたBotロールが必要です。

Renderでは `python main.py` で起動します。HTTPは `0.0.0.0` と環境変数 `PORT` にバインドし、`/` がヘルスチェックです。
現在のHTTP起動にはFlaskの開発サーバーを使用しています。Discordへの接続処理は同じプロセス内で動きます。

### デプロイ時の切り替え

Renderのサービス設定で **Health Check Path を `/`** に設定してください。
`/` はHTTPの稼働確認用で、Discord接続前でも200を返します。接続完了を待つ専用の確認先はありません。
Renderの実際の設定はコード更新だけでは変わりません。

終了通知（SIGTERM）を受けた旧版は、新しいコマンドには本人限定の更新案内を返し、実行中のスラッシュコマンドは最大20秒待ってから終了します。
既定の終了猶予30秒のうち、残りは履歴保存や接続終了に使います。処理が猶予を超えた場合、完了は保証されません。
HTTPの稼働確認はコマンドを新旧どちらへ配信するかを制御するものではなく、Discord接続の引継ぎ・無停止を保証しません。
開いているクイズやプレゼントなどのボタン、短期会話履歴はメモリ上の状態なので新版へ引き継がれません。切り替え後はコマンドから開き直してください。
今回の終了待ちはスラッシュコマンドが対象で、ボタン操作・会話生成・自動投稿の完了待ちは含みません。
この変更前の旧版には終了待ちがないため、効果を確認するのは変更を反映した後の次回以降のデプロイです。

設定の詳細は [Renderのヘルスチェック](https://render.com/docs/health-checks) と [デプロイと終了処理](https://render.com/docs/deploys#graceful-shutdown) を参照してください。

## ガチャとお気に入り

初めて使う場合は、ガチャで獲得 → お気に入りに登録 → おみくじ・クイズで贈り物を入手 → プレゼント、の順で遊べます。ヘルプにもこの順序を表示します。
同じプログレスを再登録したときは確認画面を表示し、「解除する」を押すまで解除しません。「登録を続ける」や3分の期限切れでは登録を変更しません。
確認中に別のプログレスへ変更した場合、その登録を古い確認画面から解除することもできません。
プレゼント画面には、画面を開いてから操作期限が3分であることと、コマンドで開き直す案内を表示します。クイズの操作期限も3分ですが、出題画面には期限の案内文を表示しません。
称号の装着は、サーバーで称号を選択してから「装着」を押します。DMでは一覧の確認のみです。
装着した称号は、そのサーバーのプロフィールのロール欄で他の人にも見えます。
`/所持カード` のプログレス入力欄には、本人が所持するプログレスを候補として最大25人表示します。名前を入力すると候補を絞り込めます。同じ人物の別作品・別カードは1人にまとめます。

- 抽選はローカルのカタログを使用します。実行時にWikiからカードを取得しません。
- ヴィエルジュは通常UR/SR/HR/Rが1/3/14/82%。最後の枠は2.5/7.5/90/0%。7連の4回周期で初回は最後の枠がSR以上、4回目はUR確定です。
- リリンクは通常★3/★2/★1が4/26/70%。最後の枠は4/96/0%。100枚ごとのカウントで★3確定です。
- 自然に最高レアを引いても累計保証のカウントはリセットしません。
- 誕生日は日本時間で判定し、最高レア抽選内で対象者の合計50%。最高レア自体の排出率は変わりません。
- 結果はレアリティ降順。新規カードには `✨ NEW` を付けます。
- 所持・お気に入り・好感度はユーザー単位でサーバーとDM共通です。同じ人物の別名・作品をまとめて扱います。
- お気に入り画像はリリンクの保存済み画像があれば使用し、制服を優先します。登録時に衣装は指定しません。

抽選結果とカウントは保存後に表示します。短時間の連続実行や最高レア・お気に入りの排出は、一言生成の材料として渡します。
生成AIは排出率・報酬・好感度を決定しません。

## 贈り物・好感度・アルバム

通常の贈り物は14種類、特別な贈り物は「虹色の花束」です。
喜ばれる贈り物は人物ごとの設定で判定し、カテゴリー内の全アイテムを一律に扱いません。
通常は+2、喜ばれる通常の贈り物は+5、虹色の花束は+10です。

お気に入りには日本時間の日付ごとに+1します。専用の定時ジョブではなく、利用時に未反映分を反映します。
好感度の上限は常に100で、パーフェクトリンクはユーザー・プログレスごとに1回だけです。
100に達した状態で喜ばれる通常の贈り物を贈ると、好感度+0でパーフェクトリンクを達成します。虹色の花束や日次加算では達成しません。
100の状態で贈ろうとすると、品物の種類によらず「これ以上は好感度が上がらないが、本当にあげるのか？」と確認します。「贈る」で1個消費・好感度+0、キャンセル・期限切れでは消費しません。古い画面から操作しても保存直前に確認します。
リンク達成後も上限は100のままです。過去の100超えの好感度は表示・計算で100に制限し、複数段階の記録は達成済みとして扱います。過去の記録を一括削除・更新する移行は行いません。
人物を変更しても、その子の好感度・リンク達成日・アルバムは保持します。

アルバムは「お気に入り登録日」「カード全種類収集」「初めての応援ボーナス」「パーフェクトリンク達成」を記録します。
称号の定義・条件・表示順は `title_core.py`、進捗の集計は `title_store.py` で管理します。

## おみくじ・クイズの報酬

おみくじとクイズは、それぞれ日本時間の1日1回、贈り物を受け取れます。再挑戦はできますが通常報酬は増えません。
お気に入りがラッキープログレスに選ばれると、応援ボーナスでもう1個を1日1回受け取れます。
称号用の挑戦回数・結果は、通常報酬の受取済みでも判定します。

虹色の花束の確率：おみくじは大吉10%、吉5%、中吉4%、小吉3%、末吉2%、凶1%。
クイズは正解までの回答回数が1～4回で10%・5%・4%・3%です。
クイズは生成AIを使わず、保存済みプロフィールから出題します。ヒントは出身世界以外をランダムに並べ、世界を最後に出します。

## ジョージとの会話

DM、メンション、ジョージへの返信で会話できます。
Discordユーザーは表示名で呼び、名前から性別を推定しません。プログレスの呼び方は `progressGeorgeName` を使用します。
添付画像の内容は読み取りません。ガチャ・お気に入りの画像表示は保存済みの素材を使用します。

機能の質問にはローカルの説明と設定データを優先します。AIに実行やDB確認をしたような回答をさせない構成です。
短期会話履歴はチャンネル・ユーザー別で保持します。

一般のメッセージには20%の確率でリアクションを試み、成功した文章を会話参加の候補にします。
個別のやりとりや深刻な話題などは見送り、投稿成功後は1時間、見送り・失敗後は5分待ちます。
見送り理由は日本語のログで確認できます。

## 季節通知

日本時間10:00に、同日の行事と内閣府データの祝日・休日を1投稿にまとめます。
固定行事は元日、七草、バレンタイン、猫の日、ひな祭り、ホワイトデー、エイプリルフール、七夕、ハロウィン、七五三、クリスマスイブ、クリスマス、大晦日です。
誕生日の季節通知はありません。誕生日はガチャのピックアップで扱います。

設定はサーバーごとに1チャンネル。ON状態で設定を実行するとOFF、OFFなら実行チャンネルでONになります。
行事の登録・削除コマンドはありませんが、過去に保存したサーバー固有の設定は引き続き参照します。
祝日CSVは共有キャッシュを使用し、未公表の年は独自計算しません。

Bot停止中の定刻実行はできません。当日10:00以降に起動した場合は当日分を確認し、過去日分は送りません。
送信記録で重複を防止するため、通信結果が不明な投稿は自動再送しません。

## 履歴とログ

- `george_command_history`：スラッシュコマンド、引数、実行日時、ユーザー・サーバー・チャンネル。
- `george_message_history`：ジョージ宛てのDM・メンション・返信。`kind` は `dm` / `mention` / `reply`。
- メッセージ本文は30日分を保持し、次の保存時に古い分を削除します。Botの返信本文・添付画像の内容は保存しません。
- 運用ログは処理結果・ID・日本語の理由を出力します。本文・接続情報・例外本文は出力しません。
- 履歴保存の待ち件数には上限があります。保存失敗はログに残し、会話処理は継続します。

新しい順に確認するSQL：

```sql
SELECT * FROM george_command_history
ORDER BY created_at DESC, interaction_id DESC LIMIT 100;

SELECT * FROM george_message_history
ORDER BY created_at DESC, message_id DESC LIMIT 100;
```

## テストと保守

```sh
python -m unittest discover -q
```

`check_gemini.py` はモデル一覧の診断、`check_gemini.py --test` は固定プロンプトを1回送信する生成診断です。外部APIを利用します。

`scripts/` のカタログ作成・画像取得は手動の保守用です。通常起動には不要で、実行すると保存済みデータを更新するものがあります。
`inspect_database_tables.sql` は確認用、`drop_retired_tables.sql` は削除用です。コード整理のためだけに削除SQLを実行しないでください。
旧データの移行処理・重複防止用の記録は、現在も利用するため残しています。

`test_*.py` は各機能の検証です。表示文言・順序・余白も仕様として扱います。

### 保存処理と表示を分ける

ガチャはコマンド受付 → 抽選・保存 → 表示、プレゼントは検証・消費・好感度更新 → 表示の順です。
表示やAI生成に失敗しても、抽選や消費を再実行しないでください。
`collection_display.py` と `gacha_display.py` はDBの更新を行いません。
AIには確定済みの結果を渡し、排出・報酬・好感度の判定を任せません。

保存クラスは `TitleStore → PresentStore → CollectionStore → DatabaseStore` を継承しています。
接続時のテーブル準備やトランザクションもこの呼び出し順に依存します。
`HistoryWriter` はコマンドとメッセージの保存待ち処理だけを共通化し、記録する内容はそれぞれのクラスで決めます。

### 変更箇所の選び方

- 文言・余白：対象の表示関数、`discord_layout.py`、対応する表示テスト。
- コマンド追加・削除：登録処理、ヘルプ、`bot_guide.py` のQ&A、テストを一緒に確認。
- 称号：`title_core.py` の条件・順序、`title_store.py` の集計、通知・ロール表示を確認。
- 贈り物：品目は `present_catalog.py`、喜ばれる判定は `present_preferences.py`。カテゴリーだけで好みを推測しない。
- 呼び方：プログレスは `progressGeorgeName`、Discordユーザーは表示名。アカウント名から性別を推測しない。
- カード・画像：ローカルJSONと `assets/relink/` を参照。手動生成スクリプトの実行は別作業として扱う。

### 削除する前の確認

関数名だけでなく、コールバック登録・継承・テスト・保存済みデータとの対応を検索します。
コマンドが廃止されても、移行・旧データ参照・再実行防止の処理は必要な場合があります。
特に旧カードIDの移行、廃止称号の扱い、履歴の保持期間、報酬の受取記録を単なる未使用コードとして削除しないでください。

コードの整理と本番DBの削除は別作業です。確認にはSELECTを使い、削除SQLやカタログ再生成を自動実行しません。
キャラクターの手入力データ・呼称・保存済み画像は、構造整理のついでに書き換えないでください。

### 変更後の確認

1. 対象機能のテストで文言・順序・計算・再操作時の動作を確認する。
2. `python -m unittest discover -q` で全体を確認する。
3. `git diff --check` と差分で、意図しないデータ変更を確認する。
4. Discordの権限やRender・Neonへの接続は実環境で別途確認する。

テストの成功は、本番API・Discordの権限・DB接続の成功を保証しません。
ログには処理名・結果・IDを残し、メッセージ本文や認証情報、例外本文を出さない方針を保ってください。
