# George-Bot-2026

## 季節・祝日の自動投稿（日本時間10:00）

`/季節通知 設定` は通知のON・OFFを切り替えます。未設定・OFFなら実行チャンネルを投稿先にしてON、ONならOFFです。
1サーバー1チャンネルです。投稿先を変えるときは、ONなら一度OFFにしてから、新しいチャンネルで設定してください。
`/季節通知 確認` で投稿先・通知状態・共通行事と固有行事の一覧を確認、`/季節通知 設定` でON・OFFを切り替えます。すべての操作にサーバーの管理者権限が必要です。
サーバー専用で、DMには出ません。`DATABASE_URL` とチャンネルの閲覧・送信権限が必要です。

元日、バレンタイン、ホワイトデー、七夕、ハロウィン、ポッキーの日、クリスマスイブ、クリスマス、大晦日は共通登録済み。
日本の祝日・休日は [内閣府の公開CSV](https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html) を1日1回更新し、全サーバーで共有します。
公表データに含まれる移動祝日・振替休日・国民の休日を扱い、独自の推算はしません。
取得失敗時はNeonの保存済みデータを使い、当年のデータがなければ通知を見送って1時間後に更新を再試行します。

- `/季節通知 確認`: 投稿先・通知状態と行事一覧を確認。

登録・削除・切替はサーバーの管理者権限が必要です。名前60文字まで、追加と切替は合計50件/サーバー。
祝日を切り替える場合は公表名（例：スポーツの日）と一致させてください。2月29日はうるう年のみ通知します。
同じ日に複数の行事があれば1投稿にまとめ、同名の元日などは重複させません。
挨拶はGeminiが生成し、失敗時は定型文を使います。会話履歴は生成に渡しません。
設定、独自行事、祝日キャッシュ、送信記録のテーブルは初回アクセス時に自動作成します。

Bot稼働中は日本時間10:00までメモリ上で待機し、その時刻に確認します。設定・行事の追加・削除・切替・停止時も待機を解除して読み直します。毎分のDB確認は行いません。
別プロセスからの変更を拾うため最大6時間ごとに再確認し、祝日データ不足や一時的な失敗・未確定の送信準備がある場合は最大1時間後に再確認します。
10:00以降の起動・設定でも当日中なら通知します。日付が過ぎた行事は翌日に投稿しません。
サーバーごと1日1投稿で、再起動や投稿先変更でもその日の再投稿はしません。
送信直前にNeonへ記録して重複を防ぐため、送信中の停止・通信エラーでは未達でも自動再送しません。
停止操作の直前に送信を開始した投稿は届く場合があります。大量の同日行事は見出しを先頭10件に省略します。
API・DBの無料枠を消費します。Renderの停止中に定刻投稿することはできません。
`/状態` でも季節通知の監視状況を確認できます。

## 添付画像について

会話中の添付画像を読み込む機能は廃止しました。画像は取得せず、Geminiへ送信しません。画像だけでは会話を生成しません。ガチャ・お気に入りの保存済み画像表示は引き続き利用できます。

## ジョージの発言への返信

Discordの「返信」でジョージの発言を指定すれば、メンション通知をオフにしても会話できます。
返信先の台詞（最大2000文字）を今回の発言と一緒にGeminiへ渡します。
別の人との会話履歴は共有せず、返信先の公開メッセージだけ参照します。
参照できない・削除された発言や、他のユーザーへの返信にはこの仕組みで反応しません。

## おみくじ

`/クイズ`：登録済みプロフィールから出題する4択クイズです。出身世界・好きなもの・苦手なもの・座右の銘・プロフィールのヒントを問題ごとにランダムな順番に並べ、最初に1件、不正解ごとに次の1件を追加します。回答中に順番は変わらず、同じヒントは重複しません。間違えた選択肢は再選択できません。正解するとプロフィールを公開します。結果は実行した本人だけに表示し、3分で終了します。問題作成にGeminiは使いません。正解するとプレゼントを1個獲得します。報酬はおみくじとは別枠で、ユーザーごとに日本時間の1日1回（0時切替）です。正解までの回答回数に応じて、1回目10％・2回目5％・3回目4％・4回目3％でレア「虹色の花束」を抽選します。間違えた選択肢の再操作は回数に加算しません。レア以外は14種類の通常アイテムから均等抽選し、DB保存後に獲得を表示します。成績の履歴は保存せず、報酬の最終受取日・操作ID・アイテムだけを保存します。共通のコマンド履歴記録は従来どおりです。

`/おみくじ`：運勢とラッキープログレスをランダムに抽選し、ジョージの一言をGeminiで生成します。生成失敗時はジョージの定型文を使います。お気に入りの確認は行いません。

### おみくじのプレゼントと好感度

- 日本時間でその日最初の `/おみくじ` に限り、プレゼントを1個獲得します。サーバー・DMをまたいでもユーザーごとに1日1個、0時に切り替わります。お気に入り未登録でも受け取れます。2回目以降も運勢は引け、通常報酬は増えませんが、その日未受取の応援追加品は一致時に受け取れます。
- 応援ボーナス：全挑戦でラッキープログレスと実行時のお気に入り本人の一致を判定・累計し、その日最初の一致で通常プレゼントを追加で1個獲得します。通常のおみくじ報酬とは別枠で1日1回。衣装・作品の表記違いは同じ本人として判定。初回不一致でも後の挑戦やお気に入り変更後に一致すれば取得できます。同じ操作の再送では表示内容を再利用し、所持数を増やしません。
- レア「虹色の花束」の確率は、大吉10％・吉5％・中吉4％・小吉3％・末吉2％・凶1％。レア以外は、7カテゴリー各2種類、計14種類から均等に1個抽選します。
- `/お気に入り プログレス登録 プログレス:日向美海 カード:【★3】日向美海【青蘭学園制服】` のように、プログレスと所持カードを選んで登録・変更します。同じカードを再指定すると解除します。`/お気に入り プログレス確認` で紹介・好感度・記念アルバムを確認できます。
- `/お気に入り プレゼント` で所持アイテムをボタン表示。押すと1個消費し、通常＋2、好物なら合計＋5、レアは一律＋10の好感度を獲得します。画面は本人だけに表示し、1ページ6種類・3分で終了。所持数0のアイテムは贈れません。
- 好物はBot独自のカテゴリー相性です。present_catalog.pyでプロフィールの好きなものから最大2カテゴリーを選び、該当しない子は性格・紹介文から選定、それでも未一致なら花・癒やしを設定します。全213人に1〜2カテゴリーがあり、各カテゴリー2品とも好物（＋5）。未知の名前は推測しません。AI・外部通信は使いません。
- 好感度はユーザーとプログレス本人ごとに共通で、衣装・作品・お気に入りの変更や解除で消えません。最初の上限は100。現在の上限に達した状態で喜ばれる贈り物を1個贈ると、パーフェクトリンクが1段階上がり上限＋100。100でⅠ（上限200）、200でⅡ（上限300）、300でⅢ（上限400）と続きます。節目の1個は消費し好感度＋0、到達しただけ・レア品では段階が上がりません。上限では他の贈り物も消費・＋0です。以降も贈答を続けられ、好感度による恋人設定はありません。
- パーフェクトリンクはお気に入り確認とプレゼント画面で段階・好感度/現在の上限・10マスのゲージを表示。段階は george_perfect_link_levels、最初の達成日時は従来の george_perfect_links に保存します。旧データの達成済みはⅠとして扱い、元の日付と称号を保持。再起動・別衣装・別作品・変更解除でも本人単位で引き継ぎます。旧好感度100だけでは自動達成しません。
- 記念アルバムは初登録日・カード全種類収集日・パーフェクトリンク達成日を日本時間の日付で表示します。最初の日時を保持し、再登録・衣装変更・別作品への変更でも同じ本人の記録は上書きしません。導入前の日時は推測せず「未記録」と表示し、導入後の操作から記録を開始します。
- Neonの既存 `DATABASE_URL` を使い、初回利用時に `george_present_daily`（最終受取日）、`george_present_items`（所持数）、`george_affection`（好感度）、`george_present_receipts`（重複消費防止）を自動作成します。クイズ報酬用の `george_quiz_daily` と記念日用の `george_favorite_album` も自動作成します。応援ボーナス用の `george_fortune_details`  も自動作成します。手動のDB操作は不要です。
- 受取・消費・好感度更新はトランザクション内で保存し、ユーザー単位のロックと操作IDで重複を防ぎます。受取履歴は最新1日だけ、消費の再送防止記録は7日を超えた分を次の贈答時に整理します。アイテムと好感度は残ります。保存先の障害は画面で案内します。追加のGemini生成・定期ポーリングはありません。

コマンドは全体登録に統一し、起動時に参加サーバーの旧サーバー別登録を削除します。
Logsの `Commands synced globally:` と `Guild command duplicates cleared:` で確認できます。
Discordの候補表示が古い場合はアプリを再読み込みしてください。
Developer PortalのGeneral InformationにあるInteractions Endpoint URLは空欄にしてください。
このBotはGatewayでコマンドを受け取り、Flaskはヘルスチェック専用です。

## 称号

`/称号` は本人だけに表示する獲得一覧です。候補を選び「装着」で、そのサーバーのプロフィールに称号ロールを1個だけ表示します。「解除」も本人が操作できます。変更をチャンネルへ投稿しません。DMでは一覧のみ利用できます。

獲得済み称号はユーザー共通で永久に保持し、装着するものはサーバーごとに選べます。別サーバーで好感度を上げ直す必要はありません。20件ごとのページ切替、操作画面は3分で終了します。

| 獲得条件 | 称号 |
|---|---|
| クイズの初回正解を累計10回 | 青蘭学園の知恵袋 |
| おみくじを累計10回 | 神頼み |
| 応援ボーナスを初獲得 | エール・フレンドを受けし者 |
| 通常アイテム全14種類を贈る（相手を問わず） | ソムリエの証 |
| 好感度100で喜ばれる贈り物を贈る | 👑 ○○の右腕 |
| その子に喜ばれる通常の贈り物を累計3個贈る | 🎖️ ○○の良き理解者 |
| 異なる5人で好感度100 | エール・フレンドを繋ぎし者 |
| ガチャ実行時のお気に入り本人のUR／★3を引く | 青蘭学園の熟練アルドラ |

クイズ・おみくじの称号は全挑戦を集計します。アイテム報酬のみそれぞれ1日1回です。初回正解は出題された1問の最初の回答で正解することです。プレゼントは実際に消費・保存された操作だけを数え、操作IDで再送を除外します。再会は作品・衣装が違っても本人が同じなら対象です。


「○○の右腕」は好感度100で喜ばれる贈り物を贈りパーフェクトリンクした時に取得。既存のパーフェクトリンク達成済みの子も対象です。「○○の良き理解者」は更新後に喜ばれる通常品を贈った個数を本人ごとに累計し、3個で取得します。過去の未記録個数は推定しません。

### 称号の装着

称号は設定コマンドなしで利用できます。Botに「ロールの管理」権限を付与し、Bot自身のロールを称号ロールより上に配置してください。各ユーザーが `/称号` から装着・解除でき、必要な称号ロールだけBotが作成します。

作成する称号ロールには権限・色を付けず、メンバー一覧の分離・メンションもOFFにします。同名の既存ロールは流用しません。Botが記録した称号ロール以外は変更しません。管理者が称号ロールに権限などを追加した場合は装着を拒否します。

プレゼント交換と交換称号は廃止しました。交換称号は一覧・装着の対象から除外し、接続時にBotが記録した交換称号ロールを削除します。権限や上下関係のために削除できなかった場合はログに記録し、次の接続時に再試行します。既存のDB履歴テーブルは削除せず、交換処理からはアクセスしません。

Neonの手動変更は不要です。`george_titles`（獲得済み）、`george_title_stats`（累計・種類）、`george_title_events`（再送防止）、`george_title_streaks`（現在の連続期間）、`george_title_roles`（Bot作成ロール）、`george_title_equipped`（サーバーごとの装着）を自動作成します。イベント記録は7日を超えたものを次の記録時に整理し、実績・獲得済み称号は残します。追加のGemini呼び出しはありません。

## 控えめな雑談参加

Botが閲覧・送信できるサーバー内の全チャンネルで、起動時から自主参加できます。
`/george_chat` コマンドや `GEORGE_CHAT_CHANNEL_IDS` の設定は不要です。
以前設定した `GEORGE_CHAT_CHANNEL_IDS` は参照しないため、削除して構いません。
DMでは自主参加せず、送られたメッセージに通常の返事をします。
会話の参照範囲と休止時間はチャンネルごとに分かれています。

時間の間隔によらず、同じチャンネルの直近の通常メッセージを最大8件、1件500文字までメモリに保持します。
返信・メンションなど個別の呼びかけが入ったときや、ジョージが直接の会話に返事したときは、この雑談用の文脈をクリアします。
メモリの8件は参加候補の判定に使います。20%の抽選に当たった直後に、同じチャンネルの過去ログを最大30件取得し、Botの発言などを除いた直近最大8件（古い順・各500文字）をGeminiへ渡します。再起動前の発言も取得範囲にあれば参照できます。ただし再起動後に参加候補がたまるまでは参加しません。返信・メンション・コマンドが現れた地点より前は参照しません。
Botに「チャンネルを見る」「メッセージ履歴を読む」権限が必要です。取得失敗・10秒のタイムアウト・取得した会話が深刻な内容の場合は、その回は参加を見送ります。会話の添付画像は読み込みません。
2人以上の直近3発言以上があり、メンション・返信・深刻な話題などを除いた候補で
リアクションと同じ20%の確率でGeminiへ参加判断を依頼します。自主投稿が成功した時は1時間、判断見送り・失敗時は5分待ってから再試行します。
通常のメンションへの返事は雑談文脈だけクリアし、自動参加の1時間待ちを延長しません。自動投稿成功時だけ1時間待ち、参加見送り・生成失敗・履歴取得失敗は5分後から再判定します。短い一言だけ投稿し、生成中に会話が進んだら投稿を控えます。
ランダムな絵文字リアクションは従来どおり20%の確率で付けます。
リアクションは雑談参加の1時間の休止とは独立して動きます。
話題の除外は単語判定とモデルの判断によるため、完全ではありません。
各チャンネルの候補会話はGeminiへ送信され、API利用枠を消費します。
保存対象は最大128チャンネルで、DBやファイルには保存しません。

メンション・DMの記憶は別で、ユーザー×チャンネルごとに直近10往復、最大256組です。
各リクエストで履歴と今回の発言をGeminiへ渡し、返事を履歴へ追加します。
どちらの記憶も再起動で消え、学習による恒久的な記憶にはなりません。

DiscordでジョージにメンションするかDMを送ると、Gemini APIで会話できます。
既存の `/プログレス 名前` と `@ジョージ pro 名前` による検索も利用できます。

## 起動

Python 3.11以上を使用します。

```powershell
python -m pip install -r requirements.txt
$env:DISCORD_TOKEN = "Discord Botのトークン"
$env:GEMINI_API_KEY = "Google AI Studioで発行したAPIキー"
$env:GEMINI_MODEL = "gemini-flash-latest"
python main.py
```

APIキーは [Google AI Studio](https://aistudio.google.com/apikey) で発行してください。
ホスティング環境では同名の環境変数をSecretsなどに設定します。
`.env.example` は設定項目の見本です。`.env` の自動読み込みは行いません。
キーやトークンはコードやGitに保存しないでください。
`GEMINI_MODEL` は省略可能です。利用可能なモデルIDに変更できます。

Discord Developer PortalのBot設定で **Message Content Intent** を有効にし、
Botにチャンネルの閲覧・メッセージ送信権限を付与してください。
既存の検索には `applications.commands` スコープも必要です。
リアクション機能にはリアクション追加・メッセージ履歴閲覧権限が必要です。

## 会話

- サーバー: `@ジョージ こんにちは！`
- DM: `こんにちは！`

履歴はチャンネルとユーザーの組み合わせごとに直近10往復を保持します。
最大256組で、上限に達すると使用中でない古い履歴から削除されます。
再起動すると履歴は消えます。同じ会話への同時リクエストは待つよう案内します。
会話として送った本文とその履歴はGoogleのGemini APIに送信されます。
APIの利用上限・料金はGoogle側の設定を確認してください。

ジョージの口調は `george_chat.py` の `SYSTEM_INSTRUCTION` で調整できます。
人物設定、短い雑談、未確認情報を断言しないルールを設定しています。
名前または登録された読みが本文に含まれる場合、`progress.py` の該当資料を最大4人分渡します。
名前のない続きの質問では、直前のユーザー発言に含まれた人物の資料を引き継ぎます。
資料の空欄は未確認として扱います。これによっても生成内容の正確さは保証されません。
ジョージは資料にある設定を自分の知識として自然な口調で話し、普段は「資料によると」などの前置きやプロフィール全項目の読み上げを避けます。親しみのある語り方にしても、資料にない面識・交友関係・体験談・伝聞は作りません。不明な点は自然に分からないと伝え、情報源を聞かれた場合は登録資料に基づくことを説明します。
自主参加する雑談でも、参照する直近の発言に人物の名前や登録された読みがあれば同じ資料を最大4人分渡します。
APIキー未設定・APIエラー時は案内を返し、検索機能は引き続き利用できます。

## 会話が失敗するとき

Discordの返答にHTTPコードまたはエラー分類を表示し、起動ログには
`Gemini request failed: type=... code=... reason=...` を出します。
APIキー・会話本文・Googleのエラー本文はログに出しません。

- HTTP 400: キー・リクエスト設定・利用地域などを確認。
- HTTP 401/403: キーとプロジェクトの権限・API制限を確認。
- HTTP 402: 支払い設定や残高を確認。
- HTTP 404: `GEMINI_MODEL` が利用可能なモデルか確認。
- HTTP 429: AI Studioの利用枠を確認。上限の種類によっては待つだけで解消しません。
